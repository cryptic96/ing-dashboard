## Phase Goal

ROADMAP goal (verbatim): Claude can answer accurate "how much" and "what did we spend" questions from the household's real transactions, on desktop, in Claude Code and on claude.ai web and mobile, through a securely exposed MCP endpoint.

The ROADMAP goal line is not written as a user story, so none is invented here (MVP framing note for the orchestrator).

This plan is the phase's tracer: after it, Claude Code's exact OAuth discovery chain, a password sign-in with explicit consent, the PKCE code exchange and a real MCP tool call all run end to end against the in-process host, through every layer the phase touches (Repository migration and stores, Domain query contract, OAuth server, sign-in pages, MCP endpoint, tool, query service).

<assumption_delta_decision>
Noun: custom connector.
Decision: no-change.
Rationale: vocabulary false positive. "Custom connector" is the claude.ai product name for adding a remote MCP server by URL; the ledger's model gains no chosen-versus-derived transition. The OAuth client identities are pre-registered constants, not a modelled entity.
</assumption_delta_decision>

<objective>
Embed OpenIddict 7.7.1 as the authorization server (research decision, replacing the separate-Authentik option), with ASP.NET Core Identity core holding logins, two pre-registered public Claude clients, a stateless MCP endpoint (SDK 2.2.0) behind its own bearer-only policy, and the first read-only tool, ledger_overview. Prove it with Claude Code's discovery chain run in-process, then prove token rotation, reuse revocation and restart survival (D-03, research assumption A1).

Purpose: retire every architectural risk of the phase (OpenIddict on the existing DbContext and naming convention, Identity next to the ApiKey default scheme, MCP auth forwarding with audience binding, issuer and resource strings, DataProtection-format tokens across a restart, SDK stateless mode) before any expansion plan builds on it.
Output: packages and lock files, login and OAuth tables (migration AddOAuthAndLogins), OAuth wiring, sign-in and consent pages, token endpoint, MCP endpoint, ledger_overview, test host and OAuth driver, integration tests.
</objective>
