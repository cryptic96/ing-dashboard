## Phase Goal

ROADMAP goal (verbatim): A tagged release deploys itself to the homelab LXC through a pipeline that cannot leak secrets. The running platform (app, PostgreSQL, Prometheus and Grafana) is locked down and ready to hold financial data before any real bank data arrives.

This plan is the GitHub half of the spine: after it, a strict semver tag on main produces an attested draft release that only the operator's approval publishes.

<objective>
Build the tag-triggered release workflow per D-01 and D-02: strict tag and main-reachability gate (tag value via env only), GitHub-hosted build and test, packaging through the shared script, build-provenance attestation with the Sigstore bundle published as a release asset (the installer verifies offline with it, needing no token), a draft release, and a deploy-environment-gated publish job that re-verifies the attestation before publishing. The run ends at "release published" (D-05). Document the GitHub-side controls the operator must set.

Purpose: SEC-07 needs an attested artifact; SEC-08 needs the human gate and GitHub-hosted-only execution.
Output: build/validate-release-tag.sh with tests, .github/workflows/release.yml, docs/releasing.md, docs/github-repository-settings.md.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag push → release workflow | Anyone able to create a tag could start a build; the tag string is attacker-influenceable input |
| build job → Sigstore / release assets | The attestation binds the artifact digest to this workflow and ref |
| deploy environment approval → publish | The human gate between a built artifact and one the LXC will install |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | tag string in shell | high | mitigate | Tag via env only; strict regex before any other use; no expression in run: (lint + acceptance grep) |
| T-03-02 | Tampering | release from a non-main commit | high | mitigate | validate-release-tag.sh checks reachability from origin/main and tag commit equals GITHUB_SHA; tag ruleset restricts creation (documented, set in go-live) |
| T-03-03 | Tampering | artifact swapped before publish | high | mitigate | Publish job re-verifies the draft zip against its bundle with signer workflow, tag source ref and GitHub-hosted runner checks; immutable releases lock assets after publish |
| T-03-04 | Spoofing | unapproved publish | high | mitigate | publish job bound to environment deploy with the operator as required reviewer and a v-tag deployment policy |
| T-03-05 | Elevation of Privilege | job token scope | medium | mitigate | Workflow permissions {}; build gets only contents/id-token/attestations write; publish only contents write; persist-credentials false |
| T-03-06 | Tampering | cache poisoning | medium | mitigate | No caches in the release workflow |
| T-03-07 | Repudiation | who released what | low | accept | Environment approvals and releases are recorded by GitHub; the attestation records workflow, ref and commit; no extra audit log needed at household scale |
</threat_model>

## Assumptions (flagged, unresolved edge probes)

- SEC-07 (unclassified probe): a tag-triggered build's attestation certificate records refs/tags/v{version}, never refs/heads/main (observed on 2026-09-27 against a public build attestation, where the certificate's source ref is the triggering ref). "Main" is therefore proven by this plan's reachability gate and, on the LXC, by checking the attested commit against main (plan 01-04), rather than by --source-ref refs/heads/main.
