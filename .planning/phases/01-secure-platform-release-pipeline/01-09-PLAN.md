## Phase Goal

ROADMAP goal (verbatim): A tagged release deploys itself to the homelab LXC through a pipeline that cannot leak secrets. The running platform (app, PostgreSQL, Prometheus and Grafana) is locked down and ready to hold financial data before any real bank data arrives.

This plan is the first provisioning slice: after it, running one script as root in a fresh Ubuntu 24.04 LXC installs every package from verified sources, creates the service accounts and secrets, and leaves PostgreSQL listening only on its socket with peer-mapped least-privilege roles.

<objective>
Resolve the research's open install-source questions with a repeatable network check that produces pinned values (PGDG PostgreSQL 18 on noble, the Grafana package's service user, the Prometheus LTS checksum, a GitHub CLI with attestation support, key fingerprints), then build the idempotent provision.sh (D-06) with its package, account and PostgreSQL modules: verified apt sources, system users and permissions, the env file and Data Protection certificate (D-07), and socket-only PostgreSQL with peer authentication (D-09) and the bootstrap roles and database (D-10, D-11).

Purpose: OPS-03 and SEC-05 on the real host, plus the SEC-02 role set created exactly as the tests expect.
Output: deploy/versions.env, deploy/provision.sh, deploy/provision.d/10-30, deploy/postgresql/*, provision.conf.example, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet package sources → root on the LXC | Every package and tarball runs with full privileges |
| provisioning → secrets on disk | The env file and certificate are created here |
| local OS users → PostgreSQL | Peer authentication decides who is which role |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-SC | Tampering | apt repositories and Prometheus tarball | high | mitigate | Key fingerprints pinned in versions.env and checked before trusting a repository; signed-by keyrings; Prometheus SHA-256 checked before extraction; no curl-to-shell (acceptance grep); pins re-checked by the network test |
| T-09-01 | Information Disclosure | database over the network | high | mitigate | listen_addresses empty; self-check fails if any TCP socket belongs to postgres; pg_hba has no host lines |
| T-09-02 | Elevation of Privilege | cross-role access | high | mitigate | pg_hba per-role peer lines with explicit ident maps; self-check proves each OS user reaches only its own role and not the migrator |
| T-09-03 | Information Disclosure | env file and certificate | high | mitigate | 640 root:ledger; password generated locally, passed via environment, never printed; files never overwritten on re-run |
| T-09-04 | Elevation of Privilege | service accounts | medium | mitigate | System users without shells or homes |
| T-09-05 | Tampering | provision.conf injection | medium | mitigate | Allow-list parser, no evaluation, root-owned file required |
| T-09-06 | Denial of Service | unattended major upgrades | low | mitigate | Grafana pinned to its minor line; PostgreSQL major is a separate package; Ubuntu security updates stay automatic |
</threat_model>
