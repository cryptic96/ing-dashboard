## Phase Goal

ROADMAP goal (verbatim): A tagged release deploys itself to the homelab LXC through a pipeline that cannot leak secrets. The running platform (app, PostgreSQL, Prometheus and Grafana) is locked down and ready to hold financial data before any real bank data arrives.

This plan is the REST authentication slice: after it, the operator creates a named key on the LXC and calls the API with it, and any call without a valid key is rejected even from the home network.

<objective>
Implement D-22: named per-client API keys created by a CLI command on the LXC, shown once, stored only as a hash, sent in the X-Api-Key header and individually revocable, with a fallback authorization policy so every REST endpoint requires a key. Add the first authenticated endpoint (GET /api/v1/status) and trust forwarded headers only from the Traefik host (D-20).

Purpose: API-02 (authentication even on the home network) before any REST endpoint carries data.
Output: token/store/handler/CLI/endpoint code, AddApiKeys migration, tests, LXC wrapper, env example, docs/rest-api.md.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN/VPN client → Traefik → REST API | Home-network devices are not trusted; each request must carry a key |
| operator shell on LXC → CLI | Key creation happens as root through the service identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-01 | Spoofing | REST endpoints | high | mitigate | Fallback policy requires an authenticated caller; endpoint-enumerating test proves 401 on every endpoint; no AllowAnonymous anywhere |
| T-06-02 | Information Disclosure | stored keys | high | mitigate | Only key id + SHA-256 of a 256-bit random secret stored; test proves no secret substring in any column; token shown once |
