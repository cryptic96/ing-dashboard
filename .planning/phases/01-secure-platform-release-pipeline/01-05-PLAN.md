## Phase Goal

ROADMAP goal (verbatim): A tagged release deploys itself to the homelab LXC through a pipeline that cannot leak secrets. The running platform (app, PostgreSQL, Prometheus and Grafana) is locked down and ready to hold financial data before any real bank data arrives.

This plan is the backup slice: after it, the finance database is dumped nightly and before every migration, encrypted to a key the LXC cannot use, pruned on a grandfather-father-son schedule, visibly fresh or stale in metrics, and restorable by a documented drill.

<objective>
Implement D-15 to D-18: local encrypted backups (asymmetric age, public key only on the LXC), nightly and pre-migration dumps with 7/4/12 retention, freshness and failure metrics for the alert rules, and a restore script with a drill mode and a live mode, documented step by step. The drill itself is performed in the go-live plan with the operator's private key.

Purpose: OPS-04 requires encrypted backups and a tested restore; the installer from plan 01-04 already calls ledger-backup@pre-migration.service.
Output: deploy/bin/ledger-backup, deploy/bin/ledger-restore, deploy/lib/backup.sh, backup units, tests, docs/backup-restore.md.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database → backup files on disk | Full financial history leaves PostgreSQL's access control |
| operator's password manager → LXC (restore only) | The identity is present transiently during a restore |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | backup files | high | mitigate | age encryption to public keys only; recipients file validated to contain only age1 keys; directory 700 ledger_backup, files umask 077 |
| T-05-02 | Information Disclosure | secrets inside backups | high | mitigate | Backup reads only pg_dump output; never reads the env file, certificate or identities (acceptance grep) |
| T-05-03 | Information Disclosure | identity during restore | medium | mitigate | Identity passed via stdin or tmpfs straight to age, never copied; script warns about on-disk identity files |
| T-05-04 | Elevation of Privilege | backup role | medium | mitigate | ledger_backup has pg_read_all_data only (no write); unit runs sandboxed with write access to two directories |
| T-05-05 | Denial of Service | silent backup failure or staleness | high | mitigate | pipefail, size and header checks; per-reason success/failure/timestamp metrics feed the stale (about 26 h) and failed alerts |
| T-05-06 | Denial of Service | disk loss destroys data and backups | high | accept | User decision: backups local only; offsite copies deferred; documented as accepted risk |
| T-05-07 | Tampering | live restore overwriting good data | medium | mitigate | Typed confirmation; previous database kept under a timestamped name; drill mode rehearses without touching live data |
</threat_model>
