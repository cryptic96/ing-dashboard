## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: when Claude misbehaves or is unavailable, the operator can see and undo any change over REST with an API key, audited under the key's name.

Scope note: this plan delivers the whole of D-27 for this phase: both REST endpoints the decision lists ("list recent changes" and "undo operation") over the shared audited layer. `/api/v1` is the REST API's existing path prefix, not a scope marker; the broader REST write endpoints that D-27 assigns to the web-page milestone are outside this phase by that decision.

<objective>
Add the operator REST escape hatch "list recent changes" and "undo operation" over the same audited layer MCP uses, with the API-key name as client (D-27, D-25), a dry run before the undo, the skip reporting of D-26, and the per-key write limit (D-22); document it.

Purpose: the REST half of ADV-06.
Output: IAuditedWriteStore.PlanUndoAsync, AuditService operator methods, AuditEndpoints, AuditEndpointTests, docs/rest-api.md section.
</objective>
