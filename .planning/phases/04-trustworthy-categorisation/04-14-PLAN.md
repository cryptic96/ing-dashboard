## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: the server-side half of the confirmation: a previewed change set is stored once and can be redeemed once, by the same login and client, before it expires. Plan 04-16 puts the user's dialog in front of it.

<objective>
Store change sets server-side (D-20: the confirmation must come from the user, never the model; the model only ever holds an id) with a fingerprint, an expiry and an optional token hash, and redeem them atomically once.

Purpose: ADV-07's bulk-write confirmation needs a store the model cannot forge or replay.
Output: ChangeSetModels, ChangeSetFingerprint, IPendingChangeStore, PendingChangeEntity, migration AddPendingChanges, PendingChangeStore, tests.
</objective>
