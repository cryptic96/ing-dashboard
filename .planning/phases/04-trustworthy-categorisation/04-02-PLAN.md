## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan runs in parallel with the tracer. It records how real savings transfers look (operator-assisted, answers only) and turns that shape into the synthetic scenario every categorisation test of this phase uses.

<objective>
Confirm the real shape of transfers to and from the unsynced ING savings account (CONTEXT specifics: ING usually names the savings account in the description, so the synced-account IBAN rule likely never catches them) without any real text leaving the operator's own session, then build the synthetic scenario the transfer (04-10, 04-12), rule engine (04-17), injection (04-20), own-account (04-27) and queue (04-28, 04-32) tests share (D-15, D-16, D-18, D-19, D-23).

Purpose: the savings-transfer rule in production is data the household creates after release; the code must support whichever shape is real, and the tests must exercise that shape.
Output: recorded yes/no answers in the SUMMARY, CategorisationScenario, SyntheticBankText, smoke tests.
</objective>
