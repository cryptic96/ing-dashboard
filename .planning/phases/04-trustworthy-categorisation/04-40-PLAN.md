## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: only narrow, explicit, injection-checked rules can be created; a rule that would hide money as a transfer needs the user's confirmation; removing a rule and applying a large rule to history stay under the user's control round by round.

<objective>
Guard rule creation (D-11 explicit criteria, D-15 intermediary second signal at creation, instruction checks), gate rules into transfer-kind categories as structural writes (D-16, D-21), add rule removal with a history preview (D-14), split oversized history applications into confirmed rounds (D-22), and prove that write tools take only explicit parameters (D-21). Document how a correction becomes a rule.

Purpose: CAT-07 and CAT-03 completed; ADV-07's explicit-parameter rule checked by schema.
Output: RuleValidator, AddTransferRuleApplier, UnapplyRuleApplier, change_ledger action remove_rule, rounds, WriteToolSchemaTests, tests, docs/mcp.md paragraph.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-chosen rule criteria -> rule store | A rule written now affects every future sync |
| rule -> history | Bulk rewrites of past categorisation |
| outsider text -> rule matching | Rules match text outsiders control |
