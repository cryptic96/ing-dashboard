## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: the canonical correction. "That payment request in January was concert tickets": Claude fixes it, offers a narrow rule, shows exactly which past transactions would change, and history changes only when the user confirms.

<objective>
Let Claude turn a correction into a rule (CAT-07): add a rule through MCP (D-11 explicit criteria), preview its effect on history and apply it only behind the confirmation (D-14, D-21), never touching user decisions (D-13). Guards, transfer-kind rules, removal and rounds follow in plan 04-40.

Purpose: CAT-07 and the MCP half of CAT-03.
Output: RuleInput, IRuleStore, RuleStore, SetRuleAsync with RuleAuditHandler, RuleService (AddRuleAsync, PreviewRuleApplicationAsync), ApplyRuleApplier, change_ledger actions add_rule and preview_rule_application, CorrectionToRuleTests.
</objective>

|----------|-------------|

| rule -> history | Bulk rewrites of past categorisation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-34-01 | Tampering | silent history rewrite by a rule | high | mitigate | History application only through a previewed, confirmed change set; snapshot test between preview and apply |
| T-04-34-02 | Tampering | user decisions overwritten | high | mitigate | User-sourced and built-in assignments are never candidates; test asserts the user-set row is untouched |
| T-04-34-03 | Information Disclosure | account numbers in rules | medium | mitigate | Account criterion taken from a transaction id server-side; audit states mask accounts |
