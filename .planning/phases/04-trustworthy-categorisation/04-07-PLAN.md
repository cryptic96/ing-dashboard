## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: Claude changes one transaction's category through a write tool. The change lands as one audited operation naming the client, and Claude and Grafana's reporting view both see the new category with its provenance. It completes the phase tracer started in 04-01: MCP tool, application service, audited store, database, read tools and reporting view.

<objective>
Expose the audited write pipeline through the write tool change_ledger, action recategorise for one transaction (D-21 lists a single-transaction recategorisation as a write without confirmation), with the assignment recorded as user-sourced and certain (D-09) as one audited operation naming the OAuth client (D-25). Register tool types by assembly so the following plans add tool classes without editing the endpoint, and guard the layering with a reflection test.

Purpose: prove the write path end to end and give every later write action its pattern.
Output: CategorisationService, WriteOutcome, AddLedgerCategorisation, McpCaller, ChangeTools, ChangeResults, tool registration by assembly, tests.
</objective>
