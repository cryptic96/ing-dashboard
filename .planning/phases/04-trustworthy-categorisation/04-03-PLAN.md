## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: the audited write pipeline every later write tool reuses (the ROADMAP note: a domain service writes the audit entry; the tool never writes directly). After it, one assignment written through the store lands together with one audit operation and its before and after state, or not at all. Plan 04-07 connects Claude to it through change_ledger.

<objective>
Build the audited write pipeline (D-25: operations containing items, before and after per object, client id; the tool never writes directly): domain contracts, the append-only audit tables, the store with its per-object-type handler extension point and the assignment handler, and the read side the recent_changes tool and the REST listing use. Add the category store that resolves the tree. Automatic writes stay out of the audit log (D-29).

Purpose: settle the costly audit model (D-25) once and prove it against the real database.
Output: migration AddAuditLog, AuditModels, AuditState, IAuditedWriteStore, ICategoryStore, CategoryStore, AuditedWriteStore, AssignmentAuditHandler, tests.
</objective>
