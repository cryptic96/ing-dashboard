## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here (MVP framing note for the orchestrator: run `/gsd mvp-phase 4` if a story is wanted).

This plan is the phase's tracer. After it, a transaction that carries a category shows that category, with its provenance, both in Claude's search_transactions results and in the reporting view Grafana reads. It runs through every layer the read side touches: migration and starter tree, entities and the database context, the query store, the domain row record, the query service, the MCP result shape and the reporting view.

Tracer note: one plan that also wires the audited write path through to an MCP tool needs about 25 files in this solution, far above the per-plan budget. The tracer therefore proves the data model end to end on the read side, where the output of every following plan of this phase becomes visible; the audited write store (04-03) and the first write tool (04-07) connect to it next. Nothing is released in between.

<objective>
Create the category model: an any-depth tree with English and Dutch names and a kind per node (D-01, D-03, D-06), one assignment per transaction with provenance (D-04, D-09), and the generic starter tree (D-02, D-18). Show each transaction's category and provenance in search_transactions and in reporting.transactions.

Purpose: settle the costly data-model decisions (D-01, D-04, D-06, D-09) once and prove them end to end on the read side.
Output: migration AddCategorisation, category domain models, two entities, search rows with category, CategorisationSeed, visibility and starter-tree tests.
</objective>
