## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: the pure tree logic every category feature relies on (key lookup for writes, roll-up for totals and comparisons, key generation for new categories, the removal check), built test first so the plans that use it only wire it.

<objective>
Build CategoryTree (lookup, ancestors, descendants at any depth, band, reserved keys, removal check) and CategoryKeys (immutable key from an English name), test first. Supports D-01 (any depth, totals include everything beneath), D-03 (both names, immutable key), D-05 (removal target rules) and D-06 (kind follows the band).

Purpose: one pure implementation of tree rules shared by writes (04-07, 04-26, 04-37), totals (04-18), comparisons (04-08) and the overview (04-24).
Output: CategoryTree, CategoryKeys, unit tests.
</objective>
