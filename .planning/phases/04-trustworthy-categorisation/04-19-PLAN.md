## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: clients that cannot show a dialog still need the human: they get a single-use token on a tool Claude Code prompts for on every call. Every way of forging, replaying or racing a confirmation is refused, and undoing a bulk change goes through the same confirmation.

<objective>
Complete D-20's second path: for clients that do not declare elicitation, a short-lived single-use token on apply_changes, which carries the per-call approval flag; refuse tokens from dialog-capable clients; prove every forgery, replay, expiry and race is refused. Route multi-item undo through the confirmation (D-26, D-21).

Purpose: ADV-07's confirmation for every client, and ADV-06's undo for bulk changes.
Output: token path in ConfirmationService, UndoApplier, multi-item undo preview in AuditService, TokenConfirmationTests, BulkUndoTests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-chosen tool arguments -> apply_changes | The model can choose ids and strings only |
| client transport metadata -> server | Declares elicitation per request; set by the client, not the model |
| per-call approval in the client -> server | The human's approval of each apply_changes call |
