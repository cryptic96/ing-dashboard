## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: Claude asks to recategorise several transactions at once, and the change only happens after the human confirms in the client's own dialog.

<objective>
Build the confirmation that comes from the user, never from the model (D-20): a preview stores the exact change set server-side; apply_changes redeems it only after an MRTR elicitation dialog the user accepted (the spike-verified path for the stateless 2026-07-28 server). Route multi-transaction recategorisation through it (D-21). Every bulk or structural write of this phase plugs in as a change-set kind with its own applier, registered by reflection.

Purpose: ADV-07's "bulk writes require an explicit confirmation step".
Output: ConfirmationService (dialog path), IChangeSetApplier with RecategoriseApplier, preview fields on WriteOutcome, apply_changes, McpCaller.ClientCanElicit, client options in McpTestHost, tests.
</objective>

- Per-request client capabilities: context.JsonRpcRequest.Context?.ClientCapabilities (null for clients on the older revision or without _meta); elicitation declared when its Elicitation member is not null. McpServer.ClientCapabilities is always null in stateless mode; the server's own elicit method throws in stateless mode and must not be used.
- MRTR: throw new InputRequiredException(new Dictionary<string, InputRequest> { ["confirm"] = InputRequest.ForElicitation(new ElicitRequestParams { Message, RequestedSchema with one BooleanSchema property "confirm" }) }, requestState); the client retries the same tools/call with context.Params.InputResponses["confirm"] (action accept|decline|cancel, content {confirm: true}) and context.Params.RequestState echoed. Never throw it when the request does not declare elicitation.
- [McpMeta("anthropic/requiresUserInteraction", true)] sets the tool's _meta.
- Test client: McpClientOptions.Handlers.ElicitationHandler answers dialogs; McpClientOptions.ProtocolVersion = "2025-11-25" forces the older revision.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-chosen tool arguments -> apply_changes | The model can choose ids and strings only |
| client transport metadata -> server | Declares elicitation per request; set by the client, not the model |
| client dialog -> server | The human's answer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-16-01 | Spoofing | model supplying its own confirmation | critical | mitigate | No confirmation parameter; dialog answers only through MRTR input responses; catalogue test forbids confirm-like parameters |
| T-04-16-02 | Tampering | replayed or altered request state | high | mitigate | Data Protection AEAD over change-set id, subject, client, fingerprint and expiry; atomic once-only consume |
| T-04-16-03 | Tampering | stored items altered between preview and apply | medium | mitigate | Fingerprint re-verified over the consumed items before applying |
| T-04-16-04 | Information Disclosure | dialog text | medium | mitigate | Dialog built from counts and category names only; test asserts no counterparty or description |
| T-04-16-05 | Repudiation | applied change sets | medium | mitigate | One audit operation per apply; consumed_by_operation_id links it |
| T-04-16-06 | Elevation of Privilege | read-only token redeeming a change set | high | mitigate | ConfirmTools carries the write policy; read-only connections do not list it (test) |
