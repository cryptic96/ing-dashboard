## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: Claude works through the queue and stores its proposals with reasons and confidence; until the user confirms them (plan 04-32), nothing counts.

<objective>
Store Claude's proposals (D-08: stored and held, with reason and confidence; D-09 levels) as one audited operation per batch without confirmation (D-21: storing a proposal changes no total), with supersede and cleaned, detector-checked reasons.

Purpose: CAT-06 (Claude proposes categories that the user confirms).
Output: category_proposals, migration AddCategoryProposals, SetProposalAsync with ProposalAuditHandler, ProposalService.ProposeAsync, change_ledger action propose, ProposeTests.
</objective>
