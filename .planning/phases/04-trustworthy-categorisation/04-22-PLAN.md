## Phase Goal

ROADMAP goal (verbatim): Every transaction is correctly categorised: automatically by rules where they are confident, and by Claude and the user for the rest. Every change is audited and reversible, and the household can see where the money goes and how that compares with before.

The ROADMAP goal line is not written as a user story, so none is invented here.

This plan's slice: a runaway or manipulated Claude session cannot flood the ledger: writes are limited per connection and per confirmed step, refusals are plain and counted, and the operator knows how to keep the human check switched on.

Add the write limits of D-22 (about 30 write calls per 10 minutes per connection, at most 500 transactions per confirmed step) with refusal and confirmation metrics, and the operator documentation D-20 asks for.

Purpose: ADV-07's "writes are rate-limited" and the operator side of the confirmation.
Output: WriteLimitOptions, WriteGuard, WriteMetrics, guard calls in the write tools, WriteLimitTests, docs/mcp.md section.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-driven write calls -> server | A runaway or manipulated loop can call write tools repeatedly |
| app -> Prometheus | Metric labels leave the app |
| operator settings -> Claude Code | The operator can weaken the client-side prompt |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-22-01 | Denial of Service | write flood or runaway loop | high | mitigate | Sliding-window limit per connection, 500-item cap per step, refusal metrics; operator alert in plan 04-36 |
| T-04-22-02 | Information Disclosure | metric labels | medium | mitigate | Fixed label words only; unknown values collapse to a fixed label; zero-series test |
| T-04-22-03 | Elevation of Privilege | operator settings turning the gate off | medium | transfer | Claude Code's per-call prompt is client-enforced through requiresUserInteraction; the remaining risk (an auto-answer hook or an old client) is the operator's, documented in docs/mcp.md |
| T-04-22-04 | Information Disclosure | refusal messages | low | mitigate | Fixed refusal texts with no bank data |
