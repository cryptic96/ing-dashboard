## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan gives both partners their first dashboard: after it, they open Grafana in English or Dutch and see recent transactions per account arriving, read through the read-only reporting role.

<objective>
Build the dashboard generator chosen in D-15 (a C# console tool with a small typed model of the Grafana panel types used and one EN/NL translation file), generate the first dashboard's recent-transactions part of D-16, fix the provider path so the installer actually ships the dashboards, and prove the result in a real Grafana and against the database as grafana_reader.

Purpose: DASH-05 (every dashboard in English and Dutch from one source) and DASH-07 (read-only path); every later dashboard is written in this generator.
Output: Ledger.Dashboards project, generated JSON, provider change, unit and integration tests, lint assertions.
</objective>

Model: records serialised with System.Text.Json in declaration order using one fixed JsonSerializerOptions (camelCase names, null properties omitted, WriteIndented with two-space indentation, NewLine set to "\n", relaxed encoder so Dutch text stays readable); panels are serialised by their runtime type so no type discriminator is emitted. translations.json holds one object per language ("en", "nl") mapping keys to text; it is an embedded resource. Translator.T throws with the key name when a key is missing or empty and records every used key.

Definitions/SyncDashboard.cs builds, for a given language: uid ledger-sync-en or ledger-sync-nl, a translated title, tags household-ledger plus the language code, editable false, schemaVersion 41, timezone Europe/Amsterdam, time now-30d to now, a link to the other language's dashboard (url /d/ followed by its uid), and an account query variable on the reporting datasource (SELECT display_name AS __text, account_key AS __value FROM reporting.accounts ORDER BY display_name, account_key; multi, include-all, refreshed on load). The first panel is a full-width table titled "Recent transactions" in English and "Recente transacties" in Dutch, with a translated description stating it shows at most 500 transactions and that a narrower time range reaches older ones. Its query selects effective_date, account_name, amount, currency, counterparty_name, description, status and match_flag from reporting.transactions where account_key IN (${account:sqlstring}) and $__timeFilter(effective_at), ordered by effective_date DESC, first_seen_at DESC, transaction_id DESC, LIMIT 500, format table. An organize transformation renames every column to translated headers. Value mappings turn status pending and booked into translated text (pending coloured) and match_flag ambiguous into a translated "unclear match" marker (coloured), per D-16. Amounts show two decimals. Panel ids are sequential from 1.
