## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan starts the real-consent spike (D-01) in parallel with the build (D-03): after it, the operator knows which ING accounts the bank link offers, how long a consent lasts and how much history arrives, and real pending-to-booked pairs start accumulating, encrypted, outside the repository.

<objective>
Build the workstation-only spike tool outside the repository and run the first half of the spike protocol: sandbox check, spike production application in restricted mode, account-linking observation (savings coverage), ING's consent limits, the first authorisation with an immediate longest-history capture and a second capture two hours later, balance types, and the start of daily captures. Also apply the agreed mitigation for Claude's temporary SSH key (D-04).

Purpose: the spike answers four questions (savings coverage, real consent validity, real rate limits, pending-to-booked behaviour) that reshape only the Enable Banking adapter (D-03). Everything else is built against the synthetic provider meanwhile.
Output: $HOME/ledger-spike/spike.sh (not committed), age-encrypted captures (not committed), .planning/phases/02-automatic-ing-sync/02-SPIKE.md with structural findings only.
</objective>

- Base URL https://api.enablebanking.com; Authorization: Bearer JWT with header {"typ":"JWT","alg":"RS256","kid":"<application id>"} and claims iss=enablebanking.com, aud=api.enablebanking.com, iat, exp (exp at most 86400 s after iat)
- GET /application -> kid, environment (SANDBOX|PRODUCTION), redirect_urls, active, services (AIS|PIS)
- GET /aspsps?country=NL&service=AIS -> per ASPSP maximum_consent_validity (seconds), required_psu_headers, auth_methods, psu_types
- POST /auth {access{valid_until}, aspsp{name,country}, state, redirect_url, psu_type:"personal"} -> url, authorization_id
- POST /sessions {code} -> session_id, accounts[] (uid, identification_hash, account_id{iban}, name, product, currency, cash_account_type), access.valid_until
- GET /accounts/{uid}/balances -> balances[] {balance_type, balance_amount, reference_date?}
- GET /accounts/{uid}/transactions?strategy=longest|default&date_from&continuation_key -> {transactions[], continuation_key}; repeat with continuation_key until it is null, other parameters unchanged, an empty page with a key still continues
- DELETE /sessions/{session_id}
- Errors carry {error} codes such as ASPSP_RATE_LIMIT_EXCEEDED, EXPIRED_SESSION

- session: read the code with read -s (never echoed), POST /sessions, store the session id in state/session (mode 600), print only the account count, each account's cash_account_type and product presence, which fields are present (uid, identification_hash, iban, name), whether uid looks like a UUID, and access.valid_until.

Each raw response goes straight from curl into age -r "$SPIKE_RECIPIENT" -o captures/<UTC timestamp>-LABEL-a<n>-<kind>-p<page>.json.age, teeing only into a jq structural summary. With --psu it also sends Psu-Ip-Address and Psu-User-Agent. The summary per account prints: HTTP statuses and error codes, page count, transactions per page, counts per status, entry_reference presence per status, booking_date presence on pending, transaction_id presence, earliest and latest booking date, maximum amount decimals, whether any amount string is negative, currencies, balance types present and whether each has a reference_date.
- revoke: DELETE /sessions/{id}, report the resulting status and delete state/session.
- selftest (offline): generate a throwaway key and a throwaway age identity in a mktemp directory, mint a token and verify its signature with openssl dgst -verify against the throwaway public key, run the capture pipeline over a built-in synthetic transactions document (synthetic names, identifiers using the unassigned XX country code, and a unique marker string in every text field), decrypt the resulting .age file back with the throwaway identity to prove round-trip, assert the capture directory holds only .age files, and assert the printed summary contains none of the synthetic values or markers.
