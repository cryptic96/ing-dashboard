## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan makes the to-the-cent completeness check actually work against ING, which the spike showed returns only an undated expected balance (XPCD).

<objective>
Apply spike decision 4 (02-SPIKE.md "Decisions"): reconcile on the expected balance dated at fetch time, and flag drift only when it persists across two consecutive daily snapshots, so a card payment still in progress cannot raise a false alarm.

Purpose: without this the reconciliation built in plan 09 reports "unknown" forever for ING, because it requires a booked balance type with a reference date.
Output: reconciler fallback and persistence rule, fetch-time window in the balance store, flagged-drift projection for metrics and the account status view, tests. The adapter plan (13) maps ING's XPCD to BalanceKind.Expected; this plan does not touch the adapter.
</objective>
