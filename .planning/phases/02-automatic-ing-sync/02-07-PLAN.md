## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan gives the operator the guided consent flow: after it, one authenticated call, one approval in the bank app and one selection call link the accounts and start the first full-history sync; renewing later keeps all history.

<objective>
Implement D-05, D-06, D-07, D-08 and D-09 and D-11's post-link sync: the REST-only link and renew start, the single anonymous callback protected by a one-time state (D-06, reversible), account selection with display names, the consent state machine, renewal mapping by identification hash, revocation, provider selection by configuration with Production refusal of the synthetic provider, and a background dispatcher for operator-triggered syncs that carries the operator's PSU context.

Purpose: INGEST-01 (link once), INGEST-04 (explicit consent state, renewal keeps history), INGEST-05 (first sync with the longest history right after linking) and the consent-link part of API-01.
Output: Domain state token and consent state, authorization store and migration, BankLinkService, dispatcher and worker, BankEndpoints, validator changes, tests, docs and the .http file.
</objective>
