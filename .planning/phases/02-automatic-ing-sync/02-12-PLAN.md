## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan closes the spike: after it, the operator knows how ING really behaves (quota, consent length, pending-to-booked), the spike consent is gone, and the adapter plan has concrete, operator-approved values to apply.

<objective>
Finish the spike protocol (D-01 steps S5 to S7): add the in-memory analyze step and a quota probe to the spike tool, let the operator complete the captures, probe the quota once, analyse the pairs and revoke the spike session, then record the answers and let the operator choose the adapter's values from the research's decision table (D-02 applies if the savings account is not covered).

Purpose: the Enable Banking adapter is the one part of this phase that waits for these answers (D-03).
Scheduling: this plan depends only on the spike kickoff, but it is placed in wave 6 on purpose. Waves run as barriers, so an earlier wave would stop the whole build for the several days of captures the protocol needs; in wave 6 the captures accumulate while the rest of the phase is built, and only the adapter (wave 7) waits for it.
Output: extended spike tool (outside the repository), completed .planning/phases/02-automatic-ing-sync/02-SPIKE.md with a Decisions section.
</objective>
