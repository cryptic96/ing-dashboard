## Phase Goal

ROADMAP goal (verbatim): After linking the ING accounts once, the household's real transactions arrive in the ledger every day. They are complete and never duplicated, bank-consent expiry never goes unnoticed, and both partners can see the data arriving.

This plan is the phase's tracer: after it, a (synthetic) bank consent's selected account syncs end-to-end into the ledger, idempotently, and the rows are readable by Grafana's read-only role.

<assumption_delta_decision>
Primary noun: the ledger's own account and transaction, each with an immutable internal id (uuid) and an opaque key for accounts and connections. Provider identity (session id, account uid, identification hash, entry reference or fingerprint) is a detail of one provider variant: accounts carry provider plus identification_hash as a unique pair, and every provider reference ever seen maps to one transaction through the one-to-many transaction_refs table.
Decision: promote. Rationale: a synthetic provider, the Enable Banking adapter and later a file import all feed the same ledger; keying on any provider identifier would need a data migration once real data lands (D-14).
Invariant test: the synthetic pipeline asserts every stored transaction resolves through transaction_refs to exactly one internal id and every account through (provider, identification_hash); the Enable Banking adapter plan repeats the same assertions through its own pipeline test.
</assumption_delta_decision>

<objective>
Build the provider-agnostic ingestion core and prove it end-to-end on the synthetic provider (D-03, INGEST-06): the read-only provider interface and neutral DTOs, the ledger schema with its identity model (D-14), idempotent apply with raw payload retention, sync-run records, the orchestrator, the synthetic provider, and the first reporting views read as grafana_reader (DASH-07).

Purpose: every later plan (reconciliation, linking, scheduling, balances, metrics, dashboards, the Enable Banking adapter) builds on these contracts.
Output: Domain contracts and reconciler, Repository entities, stores and the AddLedgerIngestion migration, Service orchestrator and synthetic provider, integration and role tests.
</objective>
